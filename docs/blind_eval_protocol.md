# 盲検評価セットの作成・運用手順

目的: 「この匿名化は十分か」を、実際に匿名化する対象コーパスで 1 回だけ測る。固定 OOD（11 ジャンル）は開発に使い切った回帰セットで、
外部データ（GSD-NE・OpenPII）は文体が違う。対象コーパス由来の凍結セットだけが根拠になる。

## 1. 抽出

- 対象コーパスから **200〜300 文書** を無作為抽出する（`tools/blind_set_prepare.py --n 250 --seed 42`）。ジャンル・出典・長さの偏りがあるなら
  `--stratify genre` で層化する。1 文書は 1 つの実務単位（メール 1 通、記録 1 件）。長文はそのまま入れる（分割しない）。
- 学習・開発に使った文書は除く。抽出した文書は以後、学習データにも合成テンプレートの参考にも使わない。
- 抽出物は `blind_set.source.jsonl`（原文）として保存し、SHA-256 を manifest に記録する。

## 2. 注釈方針（承認済み gold 方針 2026-09-03）

ラベルは 5 種 + 正規表現系。**「特定できるか」ではなく「NER が候補として拾うべきか」で付ける**（識別性の判断は後段の Annotator の責務）。

| ラベル | 付けるもの | 境界 |
|---|---|---|
| PERSON | 実名・通称・あだ名・ハンドル名（公人も含める）。姓のみ、名のみ、カナ・ひらがな・英字表記も | 敬称（さん・様・氏・部長 等の肩書き）と助詞は含めない。姓名間の空白・中黒は含める |
| ADDRESS | 番地を含む住所（都道府県からでも、市区町村からでも）。建物名・階・号室は同じ 1 スパンに含める | 「住所:」等のラベルは含めない。郵便番号は空白で区切られていれば `POSTAL_CODE` で別タグ（〒 は含めない） |
| LOCATION | 番地を含まない地名（都道府県・市区町村・町名・国・地域） | 「市」「区」等の行政区画語尾は含める |
| ORG | 企業・団体・官公庁・自治体・**部課名・事務局・委員会**（総務課・都市計画課も付ける）。法人格（株式会社・社会福祉法人）は含める | 「御中」「様」は含めない |
| FACILITY | 施設・建物・店舗・駅・学校・病院・**窓口・別館・センター名**（介護保険窓口・本社別館も付ける） | 種別語尾（センター・病院・駅）は含める。「1階」「302号室」は ADDRESS の一部でなければ FACILITY に含める |
| EMAIL / PHONE_NUMBER / POSTAL_CODE 等 | 正規表現検出の対象 | そのまま |

判断に迷う一般名詞（「相談窓口」「コールセンター」「担当課」のように固有の名を持たないもの）は付けない。
公人・製品名・イベント名・作品名など「匿名化対象ではないが NER が拾っても責められないもの」は `<NEUTRAL>…</NEUTRAL>` で囲み、
採点対象外（過剰マスクにも見逃しにも数えない）にする。

## 3. 作業手順

1. `PYTHONPATH=. .venv/bin/python tools/blind_set_prepare.py --input <corpus> --n 250 --out blind_set/`
   本番パイプライン（本番モデル + 正規表現 + Refiner）が下書きのタグを付けた `blind_set/blind_set.review.txt` ができる。
   本番モデルは Hub の `az225/privacy-masker-ja-pii-ner-30m`、またはローカルのモデルフォルダを `--model` で指定する。
2. レビュー担当が `review.txt` の **タグだけ** を修正する（本文の文字は変えない）。追加・削除・境界修正・ラベル変更・NEUTRAL 付与。
   下書きは見逃しを含むので、「タグの無い人名・住所が残っていないか」を主眼に全文を読む。
3. 別の担当が 20% を抽出して再確認し、食い違いは方針表に照らして決める（方針表に無いケースは表に追記する）。
4. `PYTHONPATH=. .venv/bin/python tools/blind_set_finalize.py --dir blind_set/ [--tagged authored/*.txt]`
   執筆者がタグ付きで書いた文書は `--tagged` で追加できる（原文照合なし）。lint（敬称の巻き込み・タグ外の電話/メール・同一表層のタグ有無混在）の警告を確認する。
   本文が原文と一致すること・タグの整合を検査し、`blind_eval_v1.jsonl` と SHA-256 付き manifest を出す。以後この 2 ファイルは変更しない。
5. 評価は 1 回: `PYTHONPATH=. .venv/bin/python tools/eval_all.py <モデルフォルダ> --extra blind=blind_set/blind_eval_v1.jsonl --skip-stress`
   （`<モデルフォルダ>` は本番モデル。Hub の `az225/privacy-masker-ja-pii-ner-30m` をダウンロードしたもの、またはローカルのモデルフォルダ）。
   `eval_all.py` は固定 OOD・分布内・外部評価のデータ（配布していない）も読むので、盲検セットだけで評価するなら README「評価」節の
   `privacy_masker.evaluation.evaluate(load_jsonl("blind_set/blind_eval_v1.jsonl"), engine)` を使う（同じ指標が出る）。

## 4. 合否の見方

- 主指標は **PERSON と ADDRESS の完全見逃し・危険（coverage 50% 未満）・1 文字以上の漏れ**。ORG / FACILITY / LOCATION は準識別子として次順位。
- 目安（用途が LLM 学習データの匿名化の場合）: PERSON・ADDRESS の完全見逃し 0、危険 0.5% 以下、1 文字以上の漏れ 1% 以下。
  過剰マスクは文字数で報告し、自然さの許容範囲は用途で決める。
- 漏れが出たら、その表層・文脈の型を分類してから対策を選ぶ（Refiner で決定的に直せるもの / 合成データに足すもの / モデル容量の問題）。
  **盲検セットの文書そのものを学習や規則作りに使わない。** 対策の検証には固定 OOD と分布内検証を使い、盲検セットは次版で再評価する。

## 5. 記録

- `blind_set/blind_eval_v1.manifest.json`（SHA-256・文書数・ラベル数）を記録に転記する。
- 評価結果は日付付きでリポジトリ外（手元の記録）に保存する（`tools/eval_all.py --out`）。盲検セットの原文・gold 自体もリポジトリには置かない。
